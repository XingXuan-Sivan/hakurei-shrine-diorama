# 博丽神社场景：小交互 + 可开合拉门 + 性能

- 日期：2026-10-18
- 状态：已批准，待实现
- 涉及：`src/main.js`、`src/character.js`、`src/scene/{shrine,world,props}.js`、`index.html`、`styles.css`，新增 `src/interaction.js`、`src/audio.js`、`src/omikuji.js`

## 1. 目标

在不改变现有画面取向（低多边形、单标题 HUD、无其他常驻 UI）的前提下：

1. 加五个可感知的小交互：点灵梦、悬停光标、双击复位、投赛钱、抽御神签。
2. 把主殿正面改成真正可开合的拉门（引分け遣戸），开合全程不穿模。
3. 在不降低画质的前提下优化首屏与运行时性能。

硬约束：**不穿模**、**不降低画面质量**、**不新增常驻 HUD**。

## 2. 阶段

| 阶段 | 内容 | 依赖 |

## 3. 交互规格

### 3.1 共用点按通道（`src/interaction.js`）

- `pointerdown` 记录 `(x, y, time)`；`pointerup` 时位移 < 6px 且间隔 < 450ms 判为点击。
- `pointermove` 的悬停检测节流到 90ms，不逐帧 raycast。
- 只对注册表里的对象做 raycast；注册项为 `{ object, id, onTap, onHover, cursor }`。
- 不 `preventDefault`，只消费判定为点击的事件，避免和 OrbitControls 抢手势。
- 触摸与鼠标统一走 PointerEvent；移动端不做长按。

### 3.2 灵梦（`src/character.js` 加 `poke()`）

- 点击命中角色 sprite：立即转入暂停姿态，头顶气泡出一句台词，2.6s 后回到被打断前的状态。
- 台词池 12 条，最近 6 条不重复；语气懒散、爱钱、吐槽，与角色设定一致。
- 气泡是 DOM `div`，每帧把头顶世界坐标投影成屏幕坐标；随相机距离缩放 0.85~1.15。
- 同时打开时切换台词而不是叠气泡。

### 3.3 光标与复位

- 命中可交互对象时 `cursor: pointer`；否则维持 OrbitControls 的 `grab` / `grabbing`。
- 双击非交互区域 → 调 `frameCamera(true)`（`src/main.js:135`），做一次 0.9s 的相机回位缓动。

### 3.4 赛钱箱（`world.shrine.saisen`，已在 `src/scene/shrine.js:634` 暴露）

- 点击：从相机方向抛一枚 5 円硬币（小圆柱）落进箱口，0.55s 后回收；连点最多同时 8 枚。
- 音效 WebAudio 合成：硬币落木 + 钱箱回响；首次用户手势时创建 `AudioContext`。
- 不做计数器，不加 UI。

### 3.5 御神签（`world.omikuji`，`src/scene/props.js:643`）

- 点击签架：一张纸签从架子位置飞出，0.5s 内落到镜头右下方并放大到屏高约 45%。
- 签是相机子节点（`(0.55, 0.05, -1.35)`），Canvas 纹理 256×512，绘「大吉/中吉/小吉/末吉/凶」+ 一句签文。
- 再点任意处收回；同时只存在一张。收回时反向 0.35s。
- 纸签不参与场景光照，用 `MeshBasicMaterial`，避免夜间不可读。

## 4. 主殿拉门

### 4.1 类型定位与依据

神社里真正「滑动」的是遣戸 / 舞良戸 / 障子 / 格子戸，多见于拝殿与社殿正面；本殿正门现实中多为板唐戸（双开平开）。本项目按 **社殿正面の引分け遣戸（障子）** 实现——有原型，且与现有画面一致。

依据：

- [和風建築の仕切り](https://www.weblio.jp/content/%E5%92%8C%E9%A2%A8%E5%BB%BA%E7%AF%89%E3%81%AE%E4%BB%95%E5%88%87%E3%82%8A)：板唐戸＝両開き、遣戸＝敷居と鴨居の溝に沿って開閉、舞良戸＝引き違い、蔀戸＝拝殿など。
- [JP4266915B2](https://patentimages.storage.googleapis.com/8e/41/4b/25541749b6df4b/JP4266915B2.pdf)：鴨居と敷居にそれぞれ 2 本の平行摺動溝、第 1・第 2 戸障子が係合。
- [淡水古蹟](https://www.tshs.ntpc.gov.tw/files/file_pool/1/0G258498780788578689/%E3%80%90%E5%85%A7%E6%96%87%E3%80%91%E8%87%BA%E5%8C%97%E7%B8%A3%E7%B8%A3%E5%AE%9A%E5%8F%A4%E8%B9%9F%E6%B7%A1%E6%B0%B4%E8%A1%97%E9%95%B7%E5%A4%9A%E7%94%B0%E6%A6%AE%E5%90%89%E6%95%85%E5%B1%85%E4%BF%AE%E5%BE%A9%E6%88%96%E5%86%8D%E5%88%A9%E7%94%A8%E8%A8%88%E7%95%AB-2%2888-142%29.pdf)：雨戸不用時收納於戸袋。
- [LIXIL](https://assets.lixil.com/content/dam/lixil-assets/manual/oldmpi/2007/MDD_871447.pdf)：片引き・引分けの引込み部に半壁を設ける。
- [権現造の柱間装置](https://www.jstage.jst.go.jp/article/aija/83/744/83_285/_pdf/-char/ja)：正面中央 3 間を枝唐戸、両脇と側面を葭戸。

### 4.3 状态与动画

- 默认开（park 0.75）。点击门洞或门扇切换，再次点击反向。
- 0.85s，`easeInOutCubic`；右扇领先 0.04s，收尾 0.12s 减速贴住门挡。
- 音效：滑动带通噪声 + 末端轻木响。
- 悬停门洞：内法框 emissive 提亮 0.15，提示可点。
- 开合过程中再次点击：目标反转，不跳变。

### 4.4 结构改动

1. **壁裙拆两段**（`src/scene/shrine.js:162`）：现在整条 7.18 横穿门洞，拆成左右两段，门洞通到地面。
2. **门扇后移**：从 `doorZ = 0.63` 改到两条沟 0.20 / 0.34；`shoji()` 增加 `thin` 选项，把背面暗色凹槽从 0.07 压到 0.03，两扇才能在 0.14 内叠两条轨道。
3. **内饰整体后移 0.25**：祭坛前沿现在是 `doorZ - 0.02`，无论 doorZ 取多少都会穿过门扇背面；把 `doorZ - 0.28` 一类偏移统一改为 `doorZ - 0.53`，使最前缘 ≤ 0.07，与后扇背面（0.17）留 0.10 余量。涉及 `src/scene/shrine.js:213-241` 整块。
4. **新增**：敷居、鴨居沟线、内法框、戸袋口、门挡。
5. **接口**：`buildShrine` 返回 `setDoor(open)`；目标状态由 `setDoor` 设置，`update(dt)` 里做补间。

### 4.5 防穿模判据

- 对每扇门在行程 `t ∈ [0, 1.10]` 等距采样 23 帧，与柱、壁面板、壁裙、敷居、鴨居、内法框、祭坛做 AABB 相交检测，结果必须全为空。
- 关门时两扇召合重叠 0.02，且不在同一 z 平面。
- 开门位 Z 向间隙：右扇前表面 0.3775，壁裙背面 0.39，间隙 0.0125 —— 采用薄型门扇后为 0.36 与 0.39，间隙 0.03，满足 ≥0.02。
- 全开时正面只能看到 park 保留的 0.34 门扇，其余部分被内法框 / 壁面板遮住。

## 5. 性能（P3）

先测后改，只用无损手段：

1. 基线：draw calls、帧时间 P50/P95、首屏 LCP、资源总体积（当前约 1.8MB，`reimu-atlas.png` 占 1.1MB）。
2. 手段：PNG → WebP lossless（像素完全一致）；按屏上实际像素重采样过大贴图；重复道具合批；阴影图按需更新；关键图集 `<link rel=preload>` 预加载，非关键图延迟。
3. 判据：优化前后同机位截图像素差在阈值内 + 帧时间不升 + 首屏时间下降；任一条不满足就回退该手段。

预算：资源总体积 −25%，首屏 LCP −20%，帧时间 P95 不升。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 门扇薄型化后纸面在夜间漏光 | 夜间截图逐帧确认，必要时给门加背面挡光板 |
| 内饰后移后开门视角显空 | 用 3 机位截图校准祭坛与挂轴的可见度 |
| 相机子节点的签纸在窄屏挡画面 | 按 aspect 缩放，窄屏收到屏高 38% |
| `?door=` 调大后门扇越出壁面板覆盖范围 | 上限锁 1.10，并在该值下跑防穿模检测 |
